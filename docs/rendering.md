# 渲染与回填（ContentNodes）

翻译替换发生在 `TextUtilsKt.toSpannable`（所有文本渲染的唯一汇聚点）。
替换对象必须是 `AnnotatedStructurableText` 或 `PrimitiveStructurableText` 之一
（自定义子类会被渲染器 `else` 分支抛异常）。

`ContentNodes.replaceText` 用 Kotlin data class 的通用能力重建节点树
（`getContent`/`getItems`/`componentN`/`copy`/`<init>(String)`），不逐类型枚举；
无 `copy` 的节点原样保留，不会破坏渲染。

## 文本提取（请求侧）

`TextExtractor` 决定发什么给模型：

- 只提取真正的自然语言片段（`TextContentNode`），按“段落块”切分；
- **不发送**：代码（行内代码/代码块仅计为不可翻译结构，防止模型复述代码）；
  提及/频道/emoji 等不透明节点（只贡献一个空格分隔，防止两侧单词粘连，
  也不会被模型翻译成第二个 `@提及`/`:emoji:`）；
  URL 文本块（作为定位标记，不翻译）。
- 列表项前置 `"\n" + "• "`（请求正文里列表符号可见，模型常原样回显）。
- URL 与 emoji 在请求正文占位（定位锚点）。URL 要求模型保持出现次数与顺序
  （URL 字符必须由原节点保真）；emoji 数量不符时降级回填，见下节。

## 回填对齐（译文落位）

译文先按锚点（URL/emoji）切成若干间隔，每个间隔独立对齐到该间隔的片段
（`AlignmentPlan.groupIds` 与片段一一对应）。对齐层级（`alignSpanToParts`）：

1. **空行块 1:1**：段落数目恰好等于片段数，保留段落结构；
2. **整行 1:1**：行数（含空行）恰好等于片段数且全部非空；
3. **非空行 1:1**（仅含列表项的间隔）：列表项之间只有单换行，模型按
   “每项一行”返回时，非空行数恰好等于片段数 → 逐项落位；
4. **段落级对齐**：每段译文进本段首片段、段内其余置空；**unsafe 段落**
   （片段之间夹有 emoji/行内代码/列表符号等不可翻译可见内容）拒用此级，
   强行对齐会孤立这些节点。

全部对不上 → 返回 null，调用方保留原文，不让复读或错位内容进入节点树。

### emoji 锚点降级（2026-10 修复）

上报消息为「角色提及 + `#` 标题 + 两行自定义 emoji + 文本」，图标显示
已翻译、正文仍是英文。原因：两个自定义 emoji 是定位锚点，模型回译不保留
`<:name:id>` 时旧的 `anchorsMatch` 让整条拒绝回填，状态却仍是 TRANSLATED。

修复（`alignTranslation`）：

- URL 与 emoji 校验拆开：`urlsMatch` 失败仍整条拒绝；
- `emojiAnchorsMatch` 数量不符（或数量相符但顺序对不上）时不再拒绝，改为
  `alignTokensIgnoringEmoji`：先 `stripEmojiAnchors` 剥离模型回显的锚点文本
  与行首残留空白，再忽略 emoji 切分（emoji 显示本就由原节点提供，不消费
  译文片段），仅按 URL 切间隔后走块/行逐级对齐；
- 降级路径**禁用段落级合并**（`alignSpanToParts` 的 `allowParagraphMerge=false`）：
  被降级跳过的正是夹在片段之间的 emoji，若允许合并会把除首片段外的片段
  全部置空，表现为 emoji 后的文字消失。因此降级只接受块/行逐一对得上的
  译文，模型跨段合并内容时仍保留原文。

列表项处理（`AlignmentPlan.listFlags`，与 `groupIds` 平行）：

- `PlanWalk.listLevel` / `forceNewGroup`：每个列表项强制新开段落组，
  列表结束后的正文也设边界（避免把后续段落并进最后一项）；列表本身无
  可翻译片段时不设边界。
- 列表片段回填时剥离模型回显的项目符号（`- ` / `• ` / `1. ` 等，
  `LIST_MARKER` 匹配），显示符号由原节点渲染，否则出现双符号；
  剥离后为空则保留原行（不清空列表项）。
- 普通段落里行首 `- ` 是正文内容，不剥离。

## 文本保留与边界（防丢字）

- 译文片段**按节点出现的位置分配**，不以对象身份为键：共享节点（同一
  `TextContentNode` 实例出现两次）若用身份键，后一次空片段会覆盖前一次
  译文，造成文字消失。
- 任一正文文本构造或格式容器复制失败 → 放弃整个替换结果（保留原文），
  不允许“部分成功”把其他节点清空。
- 富文本无法完整重建时返回 null，调用方保留原始对象（含文字/emoji/提及/代码）。

## 尾部空白修剪

- `normalize`：统一 `\r\n`/`\r` 为 `\n` 并去掉首尾空白（模型常以换行收尾，
  不修剪会在译文下方留下空行）。
- `trimTrailingBlank`：替换成功后自末尾删除纯空白节点（空文本节点、换行节点、
  内容全空的格式容器）；只裁尾部，正文中间空行保留；提及/emoji/代码等可见
  结构收尾时立即停止；列表逐项裁内部尾部空白但保留项目符号，整项全空才去掉
  该尾项；裁剪中 `copy` 失败只放弃该次裁剪，不让已翻译消息退回英文。
