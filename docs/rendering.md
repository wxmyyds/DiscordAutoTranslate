# 渲染与回填（ContentNodes）

翻译替换发生在 profile 选择的 `message.textConversion` 方法。具体目标由 Discord `versionCode` 对应的 Hook 配置指定；富文本替换始终保留 `AnnotatedStructurableText` 及其结构节点，不将失败的富文本改写成纯文本。

## 请求文本

`TextExtractor` 只提交可翻译的 `TextContentNode` 内容。代码、提及、频道等由原节点绘制；URL 与识别出的 emoji 作为定位标记进入请求。行内样式文本使用 `<xN>…</xN>` 标记，模型必须按原序保留。

列表项以 `• ` 标记进入请求。回填时只对列表项移除模型回显的项目符号，实际符号仍由原列表节点绘制。

## 唯一对齐规则

回填计划按原节点树建立。URL 和 emoji 锚点必须按原数量和顺序出现；样式标记必须完整匹配。缺失、重复、乱序或损坏时，整条回填失败，不忽略或剥除锚点后重新尝试。

每段只按原结构选择一种映射规则：

- 列表项：每个非空译文行对应一个列表项。
- 显式换行节点分隔的片段：逐行一一对应。
- 其他文本片段：段落块数必须与片段数及原段落组一一对应。

数量或结构不匹配时返回失败；不会把多段译文合并到首个片段，也不会逐级尝试行、段落等其它解释。样式标记缺失时同样失败。

## 失败处理

只有全部文本片段成功对齐、节点完整重建后才应用替换。任一对齐或节点构造失败，宿主继续显示原始节点树，翻译状态更新为失败，错误译文不进入缓存；用户可通过图标手动重新发起请求。

尾部空白节点及显式换行保持原样，不再运行可选修剪或备用复制路径。

## 回复预览（352017）

- `MessageView.f` 的引用模型 `c8.c` 携带被引用 `Message` 和可空的系统正文；其 `af.i` 回调直接调用 `kl.b.B0`，不经过正文的 `MessageContentView.c` 入口。
- 绑定前登记引用正文对象和消息 ID，并记录当前绑定的引用作用域。只有转换入参同时匹配引用正文对象与引用消息 ID 时，才作为回复消费者：按引用 ID/编辑时间选取规范正文快照，再以规范正文/配置哈希校验已有状态，将规范原树与已有译文交给同一个 `kl.b.B0`。预览正文是独立投影，不要求它与规范正文逐字一致，也不把整篇译文回填到投影树。绑定后登记该 ID 的重渲染消费者；预览不创建状态、不查可见文字缓存、不发请求。
- 原生回调在转换结果上添加 `LeadingMarginSpan.Standard(前导区实测宽度, 0)`，再交给 `setDraweeSpanStringBuilder`。用户名与正文视图矩形相交属于设计允许的情况，是否避让必须看首行 span 和文字布局，不能仅看视图矩形。
- 模块不得在回调之后用普通 `TextView.setText` 覆盖结果，否则会丢失首行避让和 Drawee 富文本。预览布局及 `q()` 测量继续由 Discord 自己执行。
- `getContent()` 与 `getContent$annotations()` 是不同方法；反射成员必须精确匹配，不能把元数据方法返回的 null 当成“模型正文缺失”。
- 普通回复译文复用和用户名避让已由用户设备复测确认。带图片/Embed 的复现日志（诊断版 `4924fc8`）显示规范状态为 `TRANSLATED`，但引用正文与规范正文不同，旧投影哈希校验拒绝复用；两组长度分别同为 247 和 237，具体文本投影规则未知。当前修正使用规范正文和译文，设备行为待复测。
- 规范正文快照记录该消息自身绑定时的 `getEditedTimestamp()`。引用模型、最新绑定版本及快照版本必须一致，规范正文哈希也必须匹配状态；不匹配时拒绝旧译文。读取 getter 失败不等同于正常 null；正常 null 表示宿主未提供编辑时间，不能独立证明两份不同正文绝无编辑差异，此边界仍须设备验证。系统正文不等同于正文，未将其强制替换为整篇正文。
- 从设备 Discord 352.17 APK 的 `res/layout/message_view_reply_preview.xml` 核实，正文 `MessageContentView` 设置 `maxLines=2`、`ellipsize=END`、`singleLine=false`。保留该原生设置；不按字符裁剪、不拼接省略号。诊断只读取实际行数、行数上限、截断方式与末行省略数。
- 预览消费日志区分规范状态是否存在、模型正文长度/片段数、正文是否匹配，以及是否带附件/Embed；不输出正文、消息 ID 或内容哈希。没有规范消息译文时保持原生原文。

## 结构约束

- 片段按节点出现位置消费，不能按对象身份映射；同一文本节点实例可能在树中出现多次。
- 链接、emoji、提及、代码与列表等节点由宿主原样渲染。
- 节点重建策略由版本 profile 指定：公开 data class 使用 `componentN()/copy(...)`；混淆节点只有在 `constructorFallbackTypes` 显式列入后才按已核实的字段和构造器重建，未知节点不猜测。
- 不允许部分成功：出现片段计数不符或任一节点重建失败时，整棵替换树都不提交。
