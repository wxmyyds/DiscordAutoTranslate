# 翻译文本保留与提及节点边界修复

## 事实与待确认项

用户最初反馈部分场景翻译后文字消失。第一版保护性修复后，用户确认文字恢复但部分消息仍显示英文，并进一步确认这些消息含有 @提及或频道，普通消息仍可翻译。尚无具体消息样例或设备日志；正文和回复预览的具体触发位置仍待确认。

源码中确认了两个有条件的丢字路径（不能据此断言就是用户设备上的根因）：

1. **共享文本节点被空片段覆盖**：旧 `ContentNodes.replaceText` 使用 `IdentityHashMap` 保存译片。输入若是 `[text, emoji, text]` 且两处 `text` 为同一实例，单行译文分成 `[译文, 空串]` 后，空串覆盖译文，两处文字都变空，emoji 则保留。
2. **部分重建被误判为成功**：原实现的 `changed` 在子节点构造后即置为 true，父容器 `copy` 失败只恢复父容器。若首文本位于无法复制的容器内，译文被丢弃，而后面的文字仍被清空。首文本原本为空时，就可能只剩 emoji。

本地 Discord smali 的只读检查未发现 TextContentNode 渲染或 emoji 尺寸逻辑会主动清除前文；也未证实实际输入存在共享文本实例。折叠截断、Spoiler 隐藏、不同内容版本共用状态及服务端译文内容等仍需真实样例确认。本次不修改宿主 smali、Hook 时序或翻译请求协议。

## 后续定位：提及显示名称被误当作正文

只读核对本地宿主 smali 与模块代码后，确认了与新增反馈吻合的节点边界错误：

- `TextExtractor` 将提及/频道作为占位符处理，不提取其内部显示名称。
- 原 `ContentNodes` 却递归进入所有带 `getContent()` 列表的节点，错误地把提及名称加入译片分配。
- 宿主 `UserOrRoleMentionContentNode`、`StaticChannelMentionContentNode`、`CommandMentionContentNode` 都带有 `List<ContentNode> content`，但复制方法分别为 `copy-5RCyINY`、`copy-qphDXf8`、`copy-JrbBJuM`。原查找只接受 `copy`，因此失败；第一版的保护逻辑将整条消息保留为英文。
- 能正常复制的频道节点也不应接收译文：否则名称会被改写或消耗正文译片。

修复采用明确的正文格式容器允许列表，不通过扩展 copy 方法匹配来翻译用户名。提取和替换共享 `TextExtractor.isTextContainer`；提及、频道、emoji、未知节点整节点原样保留。内容为 null 的 TextContentNode 与提取阶段一致，不消费译片。

这是已确认的代码机制；能否完全解决设备上的消息仍需新 APK 复测，不能以模拟节点单测替代宿主验证。

## 最小修复

- `ContentNodes.java`：按节点出现位置分配译片，不再按对象身份覆盖；拒绝空译文；任一正文文本构造或格式容器复制失败就放弃整个替换结果。
- `TextExtractor.java` / `ContentNodes.java`：共享格式容器边界，提及等不透明节点不遍历、不复制、不占用正文译片。
- `StructurableTextFactory.java`：富文本无法完整重建时返回 null，调用方保留原始对象（包括文字、emoji、提及、代码）。不再降级到会丢失这些结构的纯文本。
- 保留既有按换行分配译片的策略，不新增依赖、不重构调度或缓存。
- 失败诊断仅记录节点计数和既有反射错误类型，不新增消息正文或 API 密钥日志。

### 影响和限制

正常成功路径仍保留 Markdown 与结构化节点；原本是纯文本的消息照常替换。无法重建的富文本会显示原文而不是部分译文。此时后台状态仍可能是翻译成功，图标不代表节点替换一定成功；本次不调整状态模型。

本修复不保证译片仍与原有样式/表情位置精确对齐，也不解决所有折叠、Spoiler 或接口返回异常内容的情况。

## 验证

新增 `ContentNodesTest` 与 `StructurableTextFactoryTest` 覆盖共享文本/容器实例、不同译片、首容器失败、后容器失败、父容器失败、文本构造失败、空译文、富文本构造不可用、emoji-only 不被无关译文覆盖，以及正常富文本/纯文本路径。

后续新增 `OpaqueNodeTranslationTest` 及工厂集成用例：提及/频道/命令/未知节点的内部名称不被发送或替换；提及前后多段文字、样式嵌套、列表项目、只有提及、共享实例、null 文本等场景。关键断言要求正文实际成为中文，同时原提及和 emoji 实例不变，不允许“仅恢复英文”被当成成功。原失败注入用例调整为已知 Paragraph 容器，继续验证整树失败保护。

构建与单元测试：**该操作需要通过 GitHub Actions 执行。** 本地不运行 Gradle、javac 或测试。CI 结果以对应 PR / Actions 记录为准；这里不预先宣称测试通过。
