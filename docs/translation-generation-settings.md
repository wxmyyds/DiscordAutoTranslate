# 翻译输出约束与生成参数

## 本次调整

用户反馈 `hii everyone` 被扩写成“嗨！有什么需要帮助的吗？”。这不是忠实翻译；可接受的译文示例是“嗨，大家好”。

- 默认系统提示词增加问候/问题只翻译、不接话、不补充原文内容的规则和对照示例。
- 保持 `temperature: 0`：原默认值已经为 0，提高温度通常会增加随机性，并不适合这个目标。温度为 0 也不保证服务端完全确定性。
- 按用户选择添加 `frequency_penalty: 0.2`（轻度频率惩罚）。它只用于抑制重复，不能替代“只翻译”的指令；过大可能扭曲原文中需要保留的重复表达。
- 不同时添加 `top_p` 或提高 `presence_penalty`，避免不必要的采样参数改动。

默认请求模板仍把独立提示词放在 system 消息里，把原文放在 user 消息里。不会把示例作为额外的对话消息发送。

## 已安装用户如何生效

模块始终优先使用已保存的配置，升级 APK **不会覆盖**旧提示词或自定义请求模板。

使用默认 OpenAI 兼容 Chat Completions 模板的用户：

1. 安装当前 PR 最新的 GitHub Actions APK，并使 Discord 加载更新后的模块。
2. 打开模块设置，仅清空“系统提示词”和“JSON 请求模板”两项，再保存；这两项会按现有规则回落并保存为新版默认值。
3. 不清空 API URL、密钥、模型名等连接配置。若保存提示 LSPosed 未连接，先解决连接问题，不要假定保存已生效。
4. 保存成功后重新进入设置，确认模板包含 `"temperature":0` 和 `"frequency_penalty":0.2`，提示词含 `hii everyone` 示例。
5. 重新查看或发送测试消息，必要时重启 Discord 确保模块及配置已更新。提示词/模板参与配置版本计算，更新生效后旧配置的译文缓存不再匹配。

**使用自定义非 Chat Completions 接口时，不要直接清空请求模板。** 保留接口格式，按服务商文档调整对应参数，并确保模板通过 `{{system}}` 引用系统提示词（或该接口等价的指令字段）。`frequency_penalty` 的支持情况取决于接口和模型，当前无法确认用户实际服务商支持；若收到“不支持该参数”的错误，应从自定义模板移除此字段，不要盲目重试。

## 验证与限制

单元测试只验证 JSON 数值、角色/消息结构、提示词示例和自定义配置保留；不能证明远端模型一定服从。构建和自动化测试需要通过 GitHub Actions 执行，本地未运行。

模型效果需用用户实际接口验证，例如：

| 原文 | 期望行为 |
| --- | --- |
| `hii everyone` | 仅给出“嗨，大家好”等忠实译文，不追加提供帮助的问句 |
| `Can you help me?` | 翻译成“你能帮我吗？”，不要实际回答问题 |
| `Hi! Is there anything I can help you with?` | 原文本身含提供帮助的问句，应正常翻译，不应因约束而删掉 |

尚未用用户的实际模型进行效果测试，不承诺仅修改参数就能彻底消除扩写。
